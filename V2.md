## Phase 1 — Multi-user + private libraries

Today the hosted app is a **public shared gallery**: no login, one library, public Blob URLs. V2 turns it into **one app, many private workspaces**.

### Goals

- Each person signs in and gets their own items, collections, and sref groups.
- Unauthenticated visitors see only a sign-in screen.
- Media is not loadable via public CDN URLs without authentication.

### Decisions (locked)


| Question                 | Decision                                                       |
| ------------------------ | -------------------------------------------------------------- |
| Who can sign up?         | **Open** — anyone can register                                 |
| Sign-in methods          | **Email + password** and **Google**                            |
| Auth provider            | **Clerk** via Vercel Marketplace                               |
| Existing production data | **Wipe** shared public uploads — fresh start per user          |
| Local dev                | **Auth optional / off** for now — disk-based library unchanged |


### Implementation outline

1. **Clerk** — sign-up, sign-in, sign-out UI (minimal; match `design_system.md`).
2. **API gate** — all `/api/`* routes require a valid session; resolve `userId` on every request.
3. **Metadata sharding** — Redis keys: `lens:db:{userId}` instead of one shared `lens:db`.
4. **Blob sharding** — paths: `users/{userId}/originals/...`, `users/{userId}/thumbs/...`.
5. **Upload tokens** — scoped to the logged-in user only.
6. **Private media** — private blobs + authenticated proxy (`/api/media/:itemId`) or short-lived signed URLs.
7. **UI** — sign-in screen before library; sign-out in nav.

### Not in Phase 1

- Invite-only signup, teams, or shared collections across users
- Billing / subscriptions
- Full bidirectional cloud sync with local `~/Pictures/LensLibrary`

## Phase 2 — Folder watching

**Problem (v1 risk #2):** import friction → library goes stale. Re-dragging Downloads works (dedupe is safe) but people forget.

**V2 fix:** watch one or more folders (e.g. `~/Downloads`, a Midjourney export folder) and auto-import new files.

### Scope

- User picks watched folder(s) in settings.
- Debounced file-system events → same import pipeline as drag-drop (hash dedupe, MJ parse, colors, thumb).
- Progress/toast: count only, no filenames (matches current upload UX).
- Local-first; cloud mode TBD (would need server-side watcher or desktop agent).

## Hosting costs

Lens has two cost profiles: **local** (free) and **hosted** (paid when you run the cloud app for yourself or others). Prices below are approximate as of mid-2026; check each provider’s pricing page before budgeting.

### Local use — $0/month

`npm start` on your Mac, library at `~/Pictures/LensLibrary`. No Vercel, Blob, Redis, or Clerk required. This remains the cheapest way to use Lens daily.

### Hosted stack


| Service | Role | Free tier (approx.) | Paid when exceeded |
| ------- | ---- | ------------------- | ------------------ |
| **Vercel** | App + API hosting | Hobby $0 (personal / non-commercial only) | **Pro ~$20/month** for commercial / multi-user |
| **Vercel Blob** | Originals + thumbnails | Hobby: 1 GB storage, 10 GB transfer · Pro: 5 GB storage, 100 GB transfer | **~$0.023/GB/month** storage · **~$0.05/GB** transfer (public) |
| **Upstash Redis** | Items, collections, metadata | 500K commands/month, 256 MB | ~$0.20 per 100K commands (pay-as-you-go) |
| **Clerk** (Phase 1) | Sign-up, email, Google | 50K monthly retained users per app | Pro ~$20–25/month (MFA, custom sessions, no Clerk branding) |

Metadata is tiny (KB per item). **Image storage and bandwidth dominate the bill.**

Optional: custom domain ~$10–15/year.

### What drives cost

1. **Storage** — Midjourney PNGs are often 2–10 MB each. Thumbs are small (~50 KB) and negligible.
2. **Bandwidth** — Every gallery browse and detail view pulls thumbs and originals from Blob.
3. **Privacy (Phase 1)** — Private blobs use **private data transfer (~$0.15/GB)**, roughly **3×** public Blob transfer (~$0.05/GB). Better privacy costs more at scale.
4. **Auth** — Clerk stays free for a long time at indie scale (50K monthly *retained* users — users who come back after their first day).
5. **API compute** — Light for Lens; usually covered by Vercel Pro’s included usage credit.

### Monthly tiers (hosted, Vercel Pro)


| Scenario | Images (approx.) | Users | Est. monthly |
| -------- | ---------------- | ----- | ------------ |
| Solo hosted demo | &lt;500 | 1 | **~$20** (Pro base; Blob within included limits) |
| Early V2 product | 1–2K | 10–50 | **~$20–25** |
| Active libraries | ~5K | 50–200 | **~$25–35** |
| Heavier SaaS | 10K+ | 200+ | **~$40–100+** (storage + transfer, especially private media) |

Redis and Clerk are typically **$0** until libraries and traffic grow large.

### Quick calculator

Use these inputs to estimate Blob cost on **Vercel Pro** (5 GB storage and 100 GB transfer included per month):

```
avgOriginalMB   = average original file size (e.g. 5 for MJ PNG)
imageCount      = total images stored across all users
thumbMB         = imageCount × 0.05 / 1000   # ~50 KB per thumb, negligible
storageGB       = (imageCount × avgOriginalMB / 1024) + thumbMB
storageOverGB   = max(0, storageGB - 5)
storageCost     = storageOverGB × 0.023        # $/month

monthlyViews    = gallery + detail loads per month (estimate)
avgViewMB       = 0.05                         # mostly thumbs; bump to 0.5–2 if full-res common
transferGB      = monthlyViews × avgViewMB / 1024
transferOverGB  = max(0, transferGB - 100)
transferCost    = transferOverGB × rate         # rate: 0.05 public, 0.15 private (Phase 1)

hostedTotal     = 20 + storageCost + transferCost + clerkCost
clerkCost       = 0 until you need Pro features or exceed free MRU tier
```

**Example — 2,000 images, 5 MB average, light browsing**

- Storage: 2000 × 5 / 1024 ≈ **9.8 GB** → 4.8 GB over × $0.023 ≈ **$0.11/month**
- Transfer: 50K thumb loads × 0.05 MB ≈ **2.4 GB** → within 100 GB included → **$0**
- **Total ≈ $20/month** (mostly Vercel Pro)

**Example — 10,000 images, active users, private media**

- Storage: ~49 GB → 44 GB over × $0.023 ≈ **$1.01/month**
- Transfer: 500 GB viewed → 400 GB over × $0.15 ≈ **$60/month** (private)
- **Total ≈ $80/month** before any Vercel compute overages

### V2 impact on cost


| Feature | Cost effect |
| ------- | ----------- |
| Clerk auth | Free at indie scale; Pro ~$20–25 if you need advanced auth |
| Per-user Blob paths | Same storage pricing, better isolation |
| Private media | Higher transfer cost (~3× vs public URLs today) |
| Multi-user | Storage and bandwidth scale with total images + usage |
| Folder watching (local) | **$0** — runs on the Mac |
| Midjourney web pull | TBD — possible extra compute/API cost |

### Cost strategy

- **Personal daily use:** stay local → **$0**
- **Hosted for others:** budget **~$20/month minimum** (Vercel Pro), then watch Blob storage and transfer in the Vercel dashboard
- **Before monetization:** set Vercel spend alerts; consider storage limits per user if costs spike
- **Cheapest hosted path early on:** small libraries, thumb-heavy browsing, defer full-res serving until needed
